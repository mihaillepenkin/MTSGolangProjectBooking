# MTSGolangProjectBooking

## Booking Service API

Сервис управления бронированиями отелей.

### Базовый URL
```
http://localhost:8080/api/booking
```

---

### 1. Создание бронирования
Создает новое бронирование номера отеля для авторизованного клиента.

**Endpoint:** `POST /api/booking`

**Тело запроса:**
```json
{
  "hotelID": 123,
  "roomID": 456,
  "checkIn": "2024-10-25T14:00:00Z",
  "checkOut": "2024-10-30T12:00:00Z"
}
```

**Успешный ответ:**
```json
{
  "url": "localhost:8083/api/payment/process?token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9"
}
```
*После успешного создания бронирования возвращается ссылка для оплаты.*

---

### 2. Получение бронирований для отеля
Возвращает все бронирования конкретного отеля для владельца отеля.

**Endpoint:** `GET /api/booking/hotelier`

**Query-параметры:**

| Параметр | Тип     | Обязательность | Описание             |

|----------|---------|----------------|----------------------|

| hotelID  | integer | Обязательно    | ID отеля для фильтрации |

**Пример запроса:**
```
GET /api/booking/hotelier?hotelID=123
```

**Успешный ответ:**
```json
{
  "bookings": [
    {
      "userID": "user-12345",
      "hotelID": 123,
      "roomID": 456,
      "totalPrice": 25000.50,
      "currency": "RUB",
      "checkIn": "2024-10-25T14:00:00Z",
      "checkOut": "2024-10-30T12:00:00Z"
    },
    {
      "userID": "user-67890",
      "hotelID": 123,
      "roomID": 457,
      "totalPrice": 18000.00,
      "currency": "RUB",
      "checkIn": "2024-11-01T14:00:00Z",
      "checkOut": "2024-11-05T12:00:00Z"
    }
  ]
}
```

---

### 3. Получение бронирований пользователя
Возвращает все бронирования текущего авторизованного пользователя.

**Endpoint:** `GET /api/booking/client`

**Query-параметры:** Отсутствуют

**Успешный ответ:**
```json
{
  "bookings": [
    {
      "userID": "current-user-id",
      "hotelID": 123,
      "roomID": 456,
      "totalPrice": 25000.50,
      "currency": "RUB",
      "checkIn": "2024-10-25T14:00:00Z",
      "checkOut": "2024-10-30T12:00:00Z"
    },
    {
      "userID": "current-user-id",
      "hotelID": 124,
      "roomID": 500,
      "totalPrice": 32000.00,
      "currency": "RUB",
      "checkIn": "2024-12-15T14:00:00Z",
      "checkOut": "2024-12-20T12:00:00Z"
    }
  ]
}
```

---

### 4. Получение занятых периодов для номера
Возвращает список занятых временных промежутков для конкретного номера отеля.

**Endpoint:** `GET /api/booking/occupied`

**Query-параметры:**

| Параметр | Тип     | Обязательность | Описание             |

|----------|---------|----------------|----------------------|

| hotelID  | integer | Обязательно    | ID отеля            |

| roomID   | integer | Обязательно    | ID номера           |

**Пример запроса:**
```
GET /api/booking/occupied?hotelID=123&roomID=456
```

**Авторизация не требуется**

**Успешный ответ:**
```json
{
  "durations": [
    [
      "2024-10-25T14:00:00Z",
      "2024-10-30T12:00:00Z"
    ],
    [
      "2024-11-10T14:00:00Z",
      "2024-11-15T12:00:00Z"
    ],
    [
      "2024-12-01T14:00:00Z",
      "2024-12-05T12:00:00Z"
    ]
  ]
}
```
*Каждый элемент массива `durations` содержит два значения: дата начала и дата окончания бронирования.*

---

### Примечания:
1. **Аутентификация:** Все эндпоинты требуют передачи JWT-токена в заголовке `Authorization: Bearer <token>`, кроме случаев, когда это явно не указано.
2. **Формат даты:** Все даты передаются в формате ISO 8601 в UTC.
3. **Валюта:** По умолчанию используется RUB.

## Payment Service API

Сервис обработки платежей для бронирований отелей.

### Базовый URL
```
http://localhost:8083/api/payment
```

---

### 1. Создание платежа
Создает новый платеж и возвращает ссылку для оплаты.

**Endpoint:** `POST /api/payment`

**Тело запроса:**
```json
{
  "price": 25000.50,
  "currency": "RUB",
  "url": "http://localhost:8080/api/webhook-callback",
  "metadata": "booking_id:789|user_id:user-12345"
}
```

**Параметры тела запроса:**

| Поле      | Тип     | Обязательность | Описание                                     |

|-----------|---------|----------------|----------------------------------------------|

| price     | number  | Обязательно    | Сумма платежа                                |

| currency  | string  | Обязательно    | Валюта платежа (RUB, USD, EUR и т.д.)        |

| url       | string  | Обязательно    | URL для webhook callback после оплаты        |

| metadata  | string  | Обязательно    | Дополнительные данные для передачи обратно   |

**Успешный ответ:**
```json
{
  "url": "http://localhost:8083/api/payment/process?token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9",
  "payment_id": "pay_1234567890"
}
```

**Пример использования:**
1. `booking-service` отправляет запрос с данными платежа
2. `payment-service` генерирует платеж и токен
3. Возвращает ссылку с токеном для оплаты
4. `booking-service` передает ссылку клиенту

---

### 2. Обработка платежа (заглушка)
Имитация процесса оплаты с вероятностным результатом: 80% успех, 20% неуспех.

**Endpoint:** `POST /api/payment/process`

**Query-параметры:**

| Параметр | Тип     | Обязательность | Описание |

|----------|---------|----------------|---------------------------------------|

| token    | string  | Обязательно    | JWT-токен с данными платежа          |

**Пример запроса:**
```
POST /api/payment/process?token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
```

**Успешный ответ (80% случаев):**
```
Payment succeeded
```

**Неуспешный ответ (20% случаев):**
```
Payment failed
```

**Что происходит после обработки:**
После обработки платежа (получения ответа), `payment-service` автоматически отправляет webhook в `booking-service`:

```
POST /api/webhook-callback
Content-Type: application/json

{
  "payment_id": "pay_1234567890",
  "status": "SUCCESS",  // или "FAILED"
  "metadata": "booking_id:789|user_id:user-12345"
}
```

**Алгоритм работы:**
1. Клиент переходит по ссылке на оплату
2. `payment-service` обрабатывает запрос
3. Генерируется случайное число от 1 до 100:
    - Если ≤ 80 → статус "SUCCESS"
    - Если > 80 → статус "FAILED"
4. Отправляется webhook в `booking-service` с результатом
5. Клиенту показывается соответствующий текст

---

### Примечания:
1. **Токен:** В токене зашифрованы `payment_id`, `price`, `currency` и другие данные платежа
2. **Webhook:** Всегда отправляется POST-запрос на URL, указанный в поле `url` при создании платежа
3. **Статусы платежей:**
    - `SUCCESS` - оплата успешно завершена
    - `FAILED` - оплата не прошла
4. **Заглушка:** В учебных целях используется вероятностная заглушка без реальной интеграции с платежными системами
